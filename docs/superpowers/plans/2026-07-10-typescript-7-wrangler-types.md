# TypeScript 7 and Wrangler Types Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade DiezmosSV to TypeScript 7.0.2 and replace `@cloudflare/workers-types` with committed Wrangler-generated runtime and binding declarations whose freshness is enforced in CI.

**Architecture:** Keep Cloudflare configuration as the source of truth by generating `worker-configuration.d.ts` with a global `CloudflareBindings` interface. Generate configured variables as strings instead of literals so the application can continue testing unknown and missing values at its fail-closed policy boundary. The application-owned `Env` type will require generated core resource bindings, make environment-dependent bindings partial, add dashboard-secret fields Wrangler cannot infer, and preserve the issuance queue's `IssuanceMessage` payload type. CI will reject any declaration that no longer matches `wrangler.toml`, its compatibility date, or the installed Wrangler/workerd runtime. Preserve Wrangler's generated bytes verbatim and scope Git's trailing-whitespace exception to this generated file only.

**Tech Stack:** TypeScript 7.0.2, Wrangler 4.107, Cloudflare Workers/workerd, Vite 8, Vitest 4, GitHub Actions.

## Global Constraints

- Keep `compatibility_date = "2026-06-02"` and `compatibility_flags = ["nodejs_compat"]` unchanged.
- Do not change application behavior, source APIs, schemas, migrations, Worker bindings, environment values, or deployment targets.
- Do not read, modify, rotate, or deploy secrets, MH credentials, or MH certificates.
- Do not deploy to Cloudflare staging or production as part of this tooling-only migration.
- Generate declarations only through the repository-pinned Wrangler CLI.
- Keep `worker-configuration.d.ts` committed and require a clean `wrangler types --check` in CI.
- Keep Git whitespace enforcement enabled repository-wide; exempt only Wrangler's generated trailing spaces in `worker-configuration.d.ts` through `.gitattributes`.
- Preserve the typed `Queue<IssuanceMessage>` contract and the optional dashboard-secret fields in the application-owned `Env` type.
- Preserve fail-closed tests for missing or unknown deployment variables by generating configured variables with `--strict-vars false`; do not weaken runtime environment-policy checks.
